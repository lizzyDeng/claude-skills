# 分析 agent · migrate（把现有票归并成业务问题）

OUT=$out

你是 router 的分析 agent。router 改了工作单位：以前一张票是一个机制，现在一张票是一个业务问题（一群人想要的一件东西，卡在哪几道墙）。这一次只做一件事：把下面的现有票按「同一群人想要的同一件东西」归并成业务问题。router 会把你的整份迁移清单交给用户确认，确认后一次落。你只读数据、写一个 JSON 文件：不写代码、不开票、不派活、不写库、不动开关。

- 项目 brief（取数入口和口径，先读）：$brief
- 时间范围（UTC 日期）：$since ～ $until（估人群规模和缺口用）

🔴 红线：会进 GitHub 的字段（title、segment、want、walls、metric、evidence）不写 uid，也不写用户原话；只写聚合数、改写过的描述和本地路径。真实对话只在本机读。只读：不写库、不动开关、不开票。

## 怎么归并

- **先自下而上归因**：从真实对话出发看他在哪一刻走、当时想要什么、她给了什么，把老票各自对应的现象归到根因上，再归并。
- **按业务目标 + 指标归并**：同一群人想要的同一件事（同一指标）只出一条。同一个根因、同一个文件不算理由。一群人的一件事被拆成的几张机制票，并成一个问题。例：「新用户不开口」和「开口几句就走」是同一目标（第一段对话聊起来，指标 = 聊到第 10 句）的两道墙，不能拆两条。
- **墙 = 根因，不是表象**：同一根因的不同症状（表象）写在根因下面，不单独成墙。每道墙写清解释了多少流失 / 未满足（人数 / 占比），按占比从大到小排。影响面小的（不到 10%，或人群不到 10%）不成墙，写进 `notes`。
- 每个问题写进 `problems`，并进来的老票编号写进它的 `absorbs`。一张老票只进一个问题。
- 老票怎么算由 router 处理，你只写 `absorbs`：已上线、验过收的，算这个问题的一次历史尝试；还在做的不打断，等它出了上线验收结论时自动记一次。
- 不对应任何用户问题的老票（纯 bug、合规、基建、工具）：不并，它们照老流程走完。
- 已经有业务票装得下的老票（同一群人想要的同一件东西）：不重复提问题，写进 `attach`：`{"ticket": "<业务票>", "absorbs": ["<老票>", …]}`，用户确认清单后，router 把老票并进那张业务票（同 `router.py absorb`）。它卡的那一步还不在那张业务票上，另写进 `walls`。
- `maint`、`close` 写空列表：迁移不提维护项，也不提议结束。

## problems 每条怎么写

- `key`：这类问题的稳定短名（英文小写加连字符），以后每周同一类问题沿用。
- `title`、`segment`（哪群人）、`want`（他们来这里要的东西）、`walls`（卡在哪：根因，不是表象，至少一道；每道写「<根因>（解释了多少：N 人 / P%；表象：…）」，按占比从大到小排）。
- `metric`：建议指标。`name`；`now` 现在是多少（聚合数）；`direction`（`up` / `down`）。
- `evidence`：本地路径加聚合数字；可以引用老票的编号。
- `impact`：三项都要有。`size` 人群规模（0–1）；`gap` 缺口（0–1）；`confidence` 把握（`low` / `mid` / `high`）。
- `absorbs`：并进来的老票编号。
- `new_evidence`：空串。

## 产出

把结果写成一个 JSON 文件，路径就是开头 OUT 那一行，格式：

```json
{"mode": "migrate",
 "problems": [{"key": "example-segment-want", "title": "示例问题", "segment": "示例人群", "want": "示例想要",
               "walls": ["示例墙"], "metric": {"name": "示例指标", "now": "示例现值", "direction": "up"},
               "evidence": ["示例：本地路径 + 聚合数；老票 T1、T2"], "impact": {"size": 0.3, "gap": 0.5, "confidence": "mid"},
               "absorbs": ["T1", "T2"], "new_evidence": ""}],
 "attach": [{"ticket": "T7", "absorbs": ["T3"]}],
 "maint": [],
 "walls": [],
 "close": [],
 "notes": "示例：影响面小的问题、说不清根因的现象"}
```

`absorbs` 里的票号必须是上面「现有票」里的老票，一张老票只能出现一次（不能既在某个问题的 `absorbs`、又在 `attach` 里）；`attach`、`walls` 里的票必须是已有的业务票。不合规整份产出会被拒。
