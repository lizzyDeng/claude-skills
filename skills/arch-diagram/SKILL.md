# arch-diagram — 系统架构图绘制方法论

任何项目做系统设计时画图的统一手法。产出 = 自包含单文件 HTML（手工定位 div + SVG
箭头 overlay），由 Python 生成器生成，人眼可核对、可进版本库、浏览器直开。

## 🔴 硬规则（用户拍板，违反 = 返工）

1. **禁 mermaid、禁一切自动布局**——布局信息本身承载架构判断（什么挨着什么、什么在哪层跑），必须手工定位。
2. **模块命名名词化**——盒子标题 = 架构构件名（名词短语），不是它为用户做的事。
   盒子是在声明一个构件的存在：能定位（挂在哪个进程/模块/表）、能指派 owner、能被
   【接】【修】【删】；用户故事描述的是效果，效果没有位置，故事式命名会让图退化成
   feature 清单。三个判别式：
   - **造句测试**：标题能填进「___ 挂在哪个进程/模块/哪张表」才算构件名
     （「记忆写入」能答，「她记住你说的话」答不了）。
   - **语法测试**：不含「她/你/用户」做主语、不是完整主谓句；合格形态 =
     「对象+动作名词」（记忆写入 / 出口门 / 附件绑定）或机制名（频控护栏 / 路由双门）。
   - **转换法**：先写用户故事 → 问「这靠什么机制实现」→ 机制名当标题，**故事不扔，
     降级为副标题/细节行**（参考实现的系统卡片即此双层结构：标题「记忆写入」+
     副标题「对话 → 记忆行：抽取、归属判定、类型准入」）。
3. **先切系统、再切子系统**——顶层图先分层（客户端 / 编排层 / 能力层 / 契约底座 / 存储），系统盘点用「N 系统 × M 子系统」卡片格，子系统图再按职责切格。
4. **泳道按「跑在哪」切**——每条横带 = 一个运行位置（浏览器 / 服务进程同步腿 / cron 后台腿 / 数据库 / 第三方云端），不按业务域切泳道。
5. **目标态图必须区分存量与动刀**：绿/黄 = 保留的既有实现，红虚线 = 本次要动的位置，动作用【】标注；图是「整合后的目标架构」不是现状梳理时，开头就写明。
6. **改图改生成器，禁止手改 HTML 产物**——产物可再生，生成器才是源。

## 视觉词汇（固定，跨项目一致）

**状态配色**（背景 / 边框）：
- 绿 `#F0FAF4` / `#3FA46F` = 已具备·在跑
- 黄 `#FFFDF4` / `#D9A31C` = 半残·在跑但有洞
- 红 `#FFF7F6` / `#D64B3A` + `border-style:dashed` = 缺失/断链·本次要动
- 紫 `#F7F5FD` / `#8E7CD8` = 待产品拍板；也用于第三方云端服务
- 蓝 `#F4F8FB` / `#5B87A6` = 存储/契约层
- 青 `#2AA0C8` = 门/闸（路由门、feature flag 门）
- 灰 `#FFFFFF` / `#8A97A3` = 中性在产组件

**箭头**（每张画布一个 SVG overlay，5 种 marker，语义固定）：
- 灰实线 = 同步调用流
- 橙虚线 `#E08A2E` = LLM/外部 API 出网往返
- 红虚线 `#D64B3A` = 缺陷/断链（✗ 标注贴在边上）
- 绿粗线 `#2F9E62` = happy-path 回投（如 SSE 回前端）
- 紫虚线 `#7B68C8` = 异步点火（不阻塞主流程）

**动作标记**（写在盒内文案里，构成被批准的动刀清单）：
【接】接断链 ·【修】修缺陷 ·【补】补缺失 ·【开】开闸 ·【删】删死码 ·【迁】迁位置 ·【定】已定原则 ·【已裁】产品已拍板

**结构件**：固定尺寸 `.canvas`（宽统一 1720，高按内容）内绝对定位；`.lane` = 横向泳道带（背景微着色 + 左上角位置标签）；`.bx` = 组件盒（`.bt` 标题 + `.bl` 细节行）；`.elab` = 时序编号圆圈①→⑭贴在箭头中点；页面尾部 `fitAll()` 脚本按容器宽等比 scale（勿删）。

## 生成器组织

每个项目一个 `generators/` 目录：
- `gen.py` — 公共件（页面骨架、CSS、marker 定义、fitAll 脚本）
- 每张图一个 `*.py`（overall / dataflow / 各子系统…）— 数据即布局：盒子列表（x,y,w,h,状态色,标题,细节行）+ 箭头列表（path,marker）+ elab 列表
- `assemble.py` — 把各单图内联合成总文档（总文档另含：裁决卡 `.rul`、图例 `.legend`、迁移次序表、拍板清单）

🔴 **路径禁写死**：生成器里的仓路径/输出路径用相对路径或环境变量，绝对路径常量（`WT`/`HERE` 之类）换环境必炸——这是 aifriends 首个实现踩过的坑。

## 工作流

**改图**：读对应 `*.py` → 改盒子/箭头数据 → 重跑生成单图 HTML → 浏览器人眼核对 → 跑 `assemble.py` 合成总文档 → 受影响的裁决卡/图例/次序表同步更新。

**新图**：抄同项目现有 `*.py` 起步（别从零写）：先定泳道（运行位置）→ 摆盒子（名词化模块名 + 状态色）→ 连箭头（选对 marker 语义）→ 补 `.elab` 时序编号。

**新项目首次落地**：从参考实现整目录拷 `generators/`，删掉图数据只留骨架，再按上面次序填。

## 参考实现（首个完整落地）

`aifriends` 仓 `docs/architecture/staging-integration/`：总体五层图 + 8 系统×30 子系统卡片 + prompt 装配数据流（①→⑭时序）+ 六张子系统泳道图 + 12 步迁移次序表。入口 `staging-integration.html`，生成器齐全，是新项目起步的抄写对象。
