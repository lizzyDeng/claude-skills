## 补充 B：discover 把 router 自己的 worktree 当外部 session

根因：`tick.step1_external` 调 `discover.scan` 时，`router_branches` 传的是空集合，scan 只能靠分支名 `router/…` 认出 router 自己的 worktree。票合进 staging 后删 worktree 的那一刻，分支已经脱离（detached）。测试里用真 git 复现了：`git worktree list` 给出 `branch=''`。于是 `router-T<n>` 目录被当成外部 session，它锁的代码面被报成 conflict。

改了什么：
- `scripts/discover.py:85-98, 109`：`router_owned_worktree` 满足下面任一条就认作 router 自己的 worktree：
  - 分支是 `router/…`；
  - 分支是 state 里任一票的分支；
  - 路径是 state 里某票的 worktree；
  - 目录名是 `router-T<n>(-a<k>)`。
- `scripts/tick.py:411-426`：把 state 里当前、旧尝试、留着的旧 checkout 的分支和路径传进去。
- `scripts/router.py:440-444, 498`：conflict 项落下时，持锁的 worker 已经不在（没有 worktree 或不再持锁），就只记回答、不续跑。原来这里报「没有可续跑的 worker session」。
- `scripts/router.py:430`：`--as-router` 也能回维护票的 conflict 项，维护票的其他项照旧归用户。
- `SKILL.md:23, 115`：同步。

## 需求单内部矛盾，我的裁决

裁决原则：用户能看到并确认方案，router 不越权。

1. **「redirect --as-router 不允许」和 router 撤回之后怎么继续。** brief 写「换方向 = 出新方向卡交用户」。我加了 `redirect --new-card`：router 不写方向，只要一张新卡，卡交用户确认。`--as-router` 保留为参数，但一律拒，报错里给出两条正路。没有 `return` 时 router 可以出新卡，因为用户会在卡上确认。有 `return` 时连新卡也拒：连续没用之后的下一步只归用户。
2. **v2 时代 router 代确认的卡怎么上 prod。** 票级授权现在只覆盖「用户确认过的方案」。aifriends 现有的 T106、T112 卡都是 router 代确认的，在 prod-batch 里会显示「方向卡没经你确认」，等用户放行，router 不会自己上。这是有意的收紧，下面的兼容一节也提到了。
3. **「卡点按先后写进 walls」（第 2 条）和「按占比排序」（补充 A）。** 补充 A 是后来的纠正，以它为准：墙按解释的占比从大到小排，占比差不多时按用户路径的先后。`merge --walls-first` 可以把被并票的墙排到前面。
4. **「SKILL.md 第 7 节「回复用户的规矩」」。** 这个标题实际在第 8 节，第 7 节是上线验收。第 6、7 条都按标题放进第 8 节。
5. **方向项（direction）里哪些 router 能回。** 机械上，`next` 和 `assumption` 两类 topic 一律归用户。worker 停下来问的其他方向项，SKILL 写明 router 只答技术细节（验收口径、实现细节、代码面），方向、上线节奏、成本交给用户。代码区分不了措辞，这部分靠协议约束。
6. **merge 谁来定。** 并票改的是业务目标的结构，所以要求 `--said` 带用户原话。router 发现两张票是同一目标时，先告诉用户，用户同意再并。
