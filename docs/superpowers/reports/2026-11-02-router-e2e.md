## 执行中的全部 Ruling 与延后小问题（ledger 原文）

- Setup: Ruling: 用 worktree 而非在主 checkout `git checkout -b` — ~/.claude/skills 多为软链指主 checkout，切分支会影响其它 session — 代价：设计稿在主 checkout 留有未跟踪副本，合并前需删
- T3↔T5 external.weight/active：Ruling: 外部 session 只有 active（活动 ≤ stale_min）才占重票名额；持锁看活动 ≤ external_lock_hours(默认 24h)；活动时间=max(ledger mtime, 分支最新 commit 时间) — 否则 squash 合并后的陈旧 worktree 永久锁 her-reply-prompt，而等用户回答的 session 又会丢锁 — 代价：等用户 >24h 的外部 session 丢锁
- T4↔T9 progress 存放：Ruling: progress 与事件同写 events/<T>.jsonl（type=progress, phase）；tick 第 2 步按 ts ≥ worker.started_at 全量扫该票最后一条 progress/停止事件（不依赖游标）；第 3 步只路由 interface_changed/finding/assumption_broken，decision/overreach 由第 2 步进队列 — 否则 decision 每次都落慢路径重复唤醒 — 代价：worker 活着时发的 decision 要等进程退出才进队列（协议本就是 emit 后退出）
- T9 第 2 步重复处理：Ruling: 处理过一次的退出把 worker.pid 置 null 并记 worker.exit；card_ready 记 card_ready_at，超时检查跳过已交卡的票 — 否则 KICKOFF+死 pid 每轮都进 cards_for_review，watch 秒退死循环 — 代价：无
- T8 start ↔ T9 step6 batch.started：Ruling: 第 6 步不看 batch.started，只靠 pick_dispatch 的 start_ok 过滤；batch.started 仅供 UI — 新一周 draft 会重置 batch，若以它为闸会把上一批排队票冻住 — 代价：无
- T8 answer 续跑 ↔ T3 名额：Ruling: 用户 answer 后立即续跑，不过名额检查 — 用户刚回答，排队会让他白等 — 代价：重票可能短时超过 3
- T8 tell ↔ SKILL 方向审：Ruling: tell 加 `--resume`，worker 已退出时带收件箱续跑 — 方向审挑战需让 worker 改卡，plan 没给续跑入口 — 代价：多一个参数
- T8 start blocked_by：Ruling: GitHub blocked_by 只来自 triage depends_on；代码面排队由本地锁动态处理并写 waiting_for — 把锁冲突固化成依赖，前票 HOLD/SKIP 时后票永远卡住 — 代价：GitHub 上看不到「因代码面排队」
- T9 第 5 步「票结束清 CARGO」：Ruling: 共享 CARGO_TARGET_DIR 无法按票清，只做派重票前的体积检查 + 看板显示 — 代价：磁盘仍需人工清
- 测试文件名：Ruling: tests/router/test_cli.py 改名 test_router_cli.py — 与 tests/roadmap_radar/test_cli.py 同 basename，无 __init__ 时全量 pytest 报 import mismatch；加 __init__ 会让包名 router 撞 router.py — 代价：无
- Task 5: Ruling: scan 增加 lock_hours=24 参数与 locking 字段；活动时间再并入未提交改动文件的 mtime — 不用 conductor、不提交的手工 session 否则永远判闲置、不持锁 — 代价：编辑器自动保存会让闲置 session 显得活跃
- Task 6: Ruling: merge 加 `--match-head-commit <验过的 head>`，测试期望随之改 — 验完 CI 后若有人再推提交，不带它会合进未验的代码 — 代价：head 变了这一轮不合，下一轮重验
