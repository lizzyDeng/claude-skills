# Router Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** 新建 `/router` skill。它让一个常驻 session 完成从周报到合进 staging 的全流程：读周报、出派发单、用户说 start 后派 headless worker、收方向卡和决定、按订阅转交事件、维护本地看板。

**Architecture:** 确定性部分写成 Python 标准库脚本（`skills/router/scripts/`），router session 只通过一个 CLI（`router.py`）调用它们：状态文件、占用表、调度、事件路由、gh、进程管理、看板渲染。判断类工作由 router session 派 Opus 叶子完成：分诊、方向审、替用户做的决定；`SKILL.md` 规定流程。worker 是在 worktree 里跑的 `claude -p` 进程，协议见 `worker.md`，不改 conductor。

**Tech Stack:** Python 3 标准库（同 roadmap-radar，无第三方依赖）、pytest 9、`gh` CLI、`claude` CLI 2.1.316（`-p` / `--session-id` / `--resume` / `--output-format json`）、`git worktree`。

**Spec:** `docs/superpowers/specs/2026-11-02-router-design.md`（同目录下有 HTML 版 `2026-11-02-router-design.html` 和看板样例 `2026-11-02-router-board-mock.html`）。执行者两份都要读。

## Global Constraints

- 周报出来后只出派发单草稿：不建 issue，不起 worker；用户说 start 才派（spec §3、§5.1）。
- 一次 start 管整批。同批里排队的票解锁后自动派；用户临时加的票要单独 start（spec §5.1 第 6 条）。
- 从派发到方向卡进决定单不超过 30 分钟。超时照交，并注明还缺什么（spec §6.1）。
- 名额：重票（编译 Rust）3 个，用户自己的交互式 session 也算在内；轻票 2 个。等用户回答的 worker 不占名额，但继续锁着它的代码面（spec §9）。
- worker 执行中只在三种情况停：要花钱、核心假设被推翻、要越界（spec §6.3）。
- 事件只有 5 类：`decision`、`assumption_broken`、`overreach` 会停；`interface_changed`、`finding` 不停（spec §8）。进度另走 `progress`，只更新 UI，不路由。
- 一张票合进 staging 才算完成，这时释放锁。合并前提是 CI 检查非空且全部通过；不许用 `gh pr merge --auto`，staging 没有必需检查，`--auto` 会立刻合（spec §6.4）。
- 归用户的决定：start、方向卡确认、花钱、上 prod、真人动手。其余由 router 定，每条记进 `decisions.md`，编号 `D{n}`，可以撤回（spec §3）。
- GitHub 正文里不许出现用户 uid 或用户原话。需要时只给本地路径（spec §10）。
- prod 只读。worker 只能写 staging，写过 staging 数据要在同一个 run 里回滚（spec §10）。
- 看板：`.claude/router/board.html`，`<meta http-equiv="refresh" content="30">`，只能看不能操作。「解法」一栏在方向卡出来之前，显示 router 的线索并标注「非方案」（spec §5.4）。
- 巡检：ledger 或 worker 日志超过 45 分钟没更新，判为疑似卡住；同一步连续失败 2 次，进决定单；派重票前检查 `CARGO_TARGET_DIR` 大小（spec §4.5）。
- Lark 提醒只写件数和票号（spec §5.1）。
- 不改 `skills/conductor/`（spec §4.2）。

## Review Focus

1. **router session 在写状态时被压缩或崩溃** → 状态文件必须原子写入。读到坏文件时拒绝启动，并把坏文件备份成 `.corrupt-<ts>`，不能用空状态覆盖。见 Task 1：`test_save_is_atomic_and_corrupt_load_refuses`。
2. **worker 进程悄悄死掉**（Mac 睡眠、OOM、被 kill），没有输出最终 JSON → 标记为 `stuck` 并进决定单，绝不能当成完成。见 Task 9：`test_dead_worker_without_result_becomes_stuck`。
3. **router 重启后重读事件文件** → 同一事件只投递一次，靠游标保证。见 Task 4：`test_routing_is_idempotent_across_restarts`。
4. **CI 还没跑完，或根本没有检查** → 拒绝合并。见 Task 6：`test_merge_refuses_pending_or_empty_checks`。
5. **issue 正文混进周报里的用户 uid** → 拒绝建票，并报出命中的 uid。见 Task 6：`test_create_issue_refuses_body_with_known_uid`。

### 共享数据结构（store.py 定义，后续 Task 全部沿用）

- 状态常量：`DRAFT="draft"`（待 start）、`QUEUED="queued"`、`KICKOFF="kickoff"`、`AWAIT_CARD="await_card"`、`EXECUTING="executing"`、`VERIFYING="verifying"`、`MERGED="merged_staging"`、`AWAIT_PROD="await_prod"`、`DONE="done"`、`PAUSED="paused"`、`TAKEOVER="takeover"`、`STUCK="stuck"`、`HOLD="hold"`、`SKIP="skip"`。
- `RUNNING = {KICKOFF, EXECUTING, VERIFYING}`：占名额。
- `LOCKING = RUNNING | {AWAIT_CARD, PAUSED, TAKEOVER, STUCK}`：持锁。
- `SETTLED = {MERGED, AWAIT_PROD, DONE}`：对下游算「已解锁」。
- `state.json` 顶层结构：`{"version":1,"batch":{"id":str,"started":bool,"started_at":str|null},"seq":{"ticket":int,"decision":int,"queue":int},"tickets":{id:Ticket},"external":{worktree_path:External},"queue":[QueueItem],"cursors":{"events":{id:int},"inbox":{id:int}}}`。
- `Ticket` 字段：`id`（`T{n}`）、`title`、`issue`(int|null)、`status`、`weight`（`heavy|light`）、`origin`（`weekly|user`）、`batch`、`start_ok`(bool)、`priority`(int，越小越先)、`why`{`metric`,`users`,`evidence`}、`problem`、`problem_anchor`、`solution`{`kind`:`clue|card`,`text`,`source`}、`surfaces`[str]、`tags`[str]、`blocked_by`[ticket id]、`waiting_for`(str)、`review_flag`(bool)、`worker`{`session_id`,`pid`,`worktree`,`branch`,`log`,`started_at`,`kickoff_rounds`}、`pr`(int|null)、`stops`(int)、`fail_streak`{`step`,`count`}、`history`[{`at`,`status`}]。
- `QueueItem`：`{"id":"Q{n}","ticket":id|null,"kind":"start|card|spend|prod|handson|stuck|conflict|direction","summary":str,"blocks":int,"created_at":str}`。

`tick.run` 每轮固定按这个顺序做（**算法写死，实现者不要改顺序**）：
0. `weekly_runs_dir` 下最新一个含 `sent` 文件的周如果不等于 `state["batch"]["id"]`，且这周还没有草稿，就设 `triage_needed=<周>`。

2. 遍历 RUNNING 的票：pid 已死时，看 `read_result` 和该票最近一条 progress / 停止事件：
   - `card_ready` → 放进 `cards_for_review`（状态不变，由 router 做方向审后调 `submit-card`）。
   - `pr_opened` → VERIFYING。
   - 停止事件（同时 `stops += 1`）→ `decision` 进队列（kind 取 `spend` 或 `direction`），`assumption_broken` 进队列（kind=`direction`），`overreach` 走冲突处理。
   - 没有结果、也没有进度 → STUCK，并进队列。
3. `events.read_new`，然后对每条做 `route`：快路径直接 `deliver`；命中的外部 worktree 放进 `external_deliveries`，由 router 用 `SendMessage` 发送，发不通就写到该 worktree 的 `.claude/router-inbox.md`；`interface_changed` 和 `assumption_broken` 的订阅方调 `mark_review`；没命中的放进 `slow_path_events`。
4. 巡检：
   - RUNNING 的票，日志 mtime 超过 `stale_min` → 进队列「疑似卡住」（同一张票只报一次）。
   - `fail_streak.count >= 2` → 进队列。
   - KICKOFF 的票超过 `kickoff_budget_min` 还没出方向卡 → 在 `waiting_for` 写「超时」，并放进 `cards_for_review`，让 router 照常交卡。
5. VERIFYING 的票：找到对应 PR → `merge_if_green` 返回 True 时：状态改 MERGED、释放锁、给下游 issue 留言（合了什么、SHA、影响）、删 worktree，并加一条 `kind=handson` 的队列项「staging 走查 T…」。
6. `batch.started` 为真时：先算 `heavy_blocked`（`CARGO_TARGET_DIR` 超过 `disk_limit_gb`），再 `pick_dispatch`，然后对选中的每张票：`create_worktree` → 用 `templates/brief.md` 拼派单 → `spawn` → 状态改 KICKOFF。
7. `board.write`。队列比上一轮多了 → `notify.send("router：等你 {n} 件（{Q 编号…}）")`。
